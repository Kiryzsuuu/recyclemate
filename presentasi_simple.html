lib/services/auth_service.dart — Fungsi Login
static Future<UserModel> login({
  required String email,
  required String password,
}) async {
  try {
    // 1. Kirim email + password ke Firebase Authentication
    final credential = await _auth.signInWithEmailAndPassword(
      email: email,
      password: password,
    );

    // 2. Setelah berhasil, ambil data profil dari Firestore
    //    Firebase Auth hanya menyimpan email & uid, bukan nama, kota, dll.
    final doc = await _db
        .collection('users')
        .doc(credential.user!.uid)
        .get();

    if (!doc.exists) {
      throw Exception('Data user tidak ditemukan.');
    }

    // 3. Ubah dokumen Firestore menjadi objek UserModel dan kembalikan
    return UserModel.fromFirestore(doc);

  } on FirebaseAuthException catch (e) {
    // Terjemahkan kode error Firebase ke pesan yang mudah dipahami
    throw Exception(_authErrorMessage(e.code));
  }
}

Q: Bagaimana cara app tahu user sudah login atau belum?
SplashScreen mengecek FirebaseAuth.instance.currentUser. Firebase menyimpan sesi login secara lokal di perangkat. Jika tidak null berarti sudah login, langsung redirect ke /home. Jika null, redirect ke /login.
Q: Apa perbedaan peran buyer, seller, dan admin dalam kode?
Field role di Firestore collection users. UserModel punya getter isAdmin (role == 'admin') dan isSeller (role == 'seller' atau 'admin'). HomeScreen mengecek getter ini untuk menampilkan menu yang berbeda — buyer tidak lihat menu toko, admin dapat ikon panel admin.
Q: Kenapa ada fungsi _ensureAdminAccount() di main.dart?
Supaya akun admin otomatis terbuat saat pertama kali app dijalankan tanpa setup manual. Fungsi ini mengecek Firestore di app_config/setup — jika sudah ada flag adminCreated: true, fungsi langsung berhenti dan tidak membuat akun baru.
Q: Apa itu StatefulWidget dan kenapa LoginScreen menggunakannya?
StatefulWidget adalah widget yang punya state yang bisa berubah. LoginScreen membutuhkan ini karena ada state yang berubah: _isLoading (tombol berubah jadi spinner saat proses login) dan _obscurePassword (toggle tampilkan/sembunyikan password). Perubahan state dipanggil dengan setState().

List<ProductModel> _applyFilters(List<ProductModel> all) {
  var products = all;

  // Filter 1: berdasarkan material (kategori chip yang dipilih)
  if (_selectedCategory != 'Semua') {
    products = products
        .where((p) => p.material == _selectedCategory)
        .toList();
  }

  // Filter 2: berdasarkan kata kunci pencarian
  if (_searchQuery.isNotEmpty) {
    final q = _searchQuery.toLowerCase();
    products = products
        .where((p) =>
            p.name.toLowerCase().contains(q) ||       // cari di nama
            p.description.toLowerCase().contains(q)) // atau di deskripsi
        .toList();
  }

  return products;
}

lib/services/api_service.dart — Query Produk dari Firestore
static Future<List<ProductModel>> getProducts({
  String? material,
  String? search,
}) async {
  // Query ke Firestore: ambil produk yang aktif, urutkan terbaru
  Query query = _db
      .collection('products')
      .where('isActive', isEqualTo: true)
      .orderBy('createdAt', descending: true);

  // Filter material bisa ditambah langsung di query Firestore
  if (material != null && material != 'Semua') {
    query = query.where('material', isEqualTo: material);
  }

  final snapshot = await query.get();
  var products = snapshot.docs
      .map((d) => ProductModel.fromFirestore(d))
      .toList();

  // Filter search dilakukan di Flutter (client-side)
  // karena Firestore tidak support full-text search
  if (search != null && search.isNotEmpty) {
    final q = search.toLowerCase();
    products = products
        .where((p) => p.name.toLowerCase().contains(q) ||
                      p.description.toLowerCase().contains(q))
        .toList();
  }

  return products;
}

Pertanyaan yang Mungkin Ditanya

Q: Apa itu FutureBuilder dan kenapa dipakai?
FutureBuilder adalah widget Flutter bawaan untuk menampilkan UI yang berbeda tergantung kondisi Future (async). Kondisi yang ditangani: ConnectionState.waiting (tampilkan loading), hasError (tampilkan pesan error), dan saat data tersedia (tampilkan grid produk). Ini cara standar Flutter untuk handle data async.
Q: Kenapa filter search dilakukan di Flutter, bukan di Firestore?
Firestore tidak mendukung full-text search secara native. Untuk mencari teks dalam string, harus dilakukan di sisi Flutter menggunakan String.contains(). Cara ini cocok untuk data berjumlah ratusan. Untuk skala ribuan produk, perlu layanan tambahan seperti Algolia.
Q: Bagaimana cara navigasi ke halaman detail produk sambil mengirim data?
Menggunakan Navigator.pushNamed(context, '/detail', arguments: product.toMap()). Di main.dart, route /detail didaftarkan di onGenerateRoute (bukan di routes biasa) karena butuh argumen dinamis berupa Map data produk yang berbeda setiap produk.
Q: Bagaimana proses pemesanan produk di halaman detail?
User mengisi form (jumlah, alamat, catatan) lalu tekan tombol Pesan. App memanggil FirestoreService.createOrder() yang membuat dokumen baru di Firestore collection orders berisi: productId, buyerId, quantity, totalPrice, alamat, dan status awal 'pending'.

lib/services/storage_service.dart — Upload Foto ke Firebase Storage
class StorageService {
  static final _storage = FirebaseStorage.instance;

  // Upload file, kembalikan URL publik yang bisa diakses dari mana saja
  static Future<String> uploadFile(
    File file, {
    String folder = 'products', // bisa diubah ke 'avatars', 'stores', dll
  }) async {
    // Buat nama file unik menggunakan timestamp agar tidak tumpang tindih
    final path = '$folder/${DateTime.now().millisecondsSinceEpoch}';

    // Upload file ke Firebase Storage
    final ref = _storage.ref(path);
    await ref.putFile(file);

    // Dapatkan URL download yang bisa digunakan sebagai src gambar
    return await ref.getDownloadURL();
  }
}

Future<void> _uploadProduct() async {
  // 1. Validasi semua input form terlebih dahulu
  if (!_formKey.currentState!.validate()) return;
  if (_imageFile == null) {
    _showError('Pilih foto produk terlebih dahulu.');
    return;
  }

  setState(() => _isLoading = true); // tampilkan loading spinner

  try {
    // 2. Upload foto ke Firebase Storage, dapatkan URL-nya
    final imageUrl = await StorageService.uploadFile(
      _imageFile!,
      folder: 'products',
    );

    // 3. Simpan data produk + URL foto ke Firestore
    await FirestoreService.createProduct({
      'name': _nameController.text.trim(),
      'price': double.parse(_priceController.text),
      'material': _selectedMaterial, // Plastik / Kayu / Kaca / dll
      'description': _descController.text.trim(),
      'imageUrl': imageUrl,           // URL foto dari Storage
    });

    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Produk berhasil diupload!')),
      );
      Navigator.pop(context); // kembali ke halaman sebelumnya
    }
  } catch (e) {
    _showError('Gagal upload: $e');
  } finally {
    if (mounted) setState(() => _isLoading = false);
  }
}

Pertanyaan yang Mungkin Ditanya

Q: Bagaimana cara foto produk disimpan? Apakah langsung ke Firestore?
Tidak bisa langsung ke Firestore karena Firestore hanya menyimpan teks, angka, dan data kecil. Foto diupload ke Firebase Storage menggunakan StorageService.uploadFile(). Hasilnya berupa URL string panjang, URL itulah yang disimpan di Firestore pada field imageUrl. Saat app butuh tampilkan gambar, pakai URL tersebut sebagai sumber gambar.
Q: Apa itu soft delete dan kenapa tidak langsung hapus dari database?
Soft delete artinya tidak benar-benar menghapus dokumen dari Firestore. Hanya field isActive yang diubah menjadi false. Alasan: data pesanan lama yang mereferensi produk tersebut tidak menjadi rusak (misalnya, riwayat pesanan pembeli masih bisa ditampilkan). Admin juga bisa melihat riwayat produk yang dinonaktifkan. Hard delete (benar-benar hapus) dilakukan khusus oleh admin.
Q: Bagaimana proses dari buyer menjadi seller?
Buyer pergi ke halaman OpenStoreScreen, mengisi nama toko dan deskripsi, lalu submit. Di backend, FirestoreService.createStore() menjalankan dua operasi: (1) membuat dokumen baru di collection stores, dan (2) mengupdate field role user di collection users dari 'buyer' menjadi 'seller'. HomeScreen kemudian menampilkan menu toko yang sebelumnya tersembunyi.
Q: Apa fungsi GlobalKey<FormState> pada form upload?
GlobalKey<FormState> adalah kunci unik yang menghubungkan widget Form dengan kode kita. Dengan memanggil _formKey.currentState!.validate(), Flutter akan menjalankan fungsi validator pada setiap TextFormField di dalam Form tersebut. Jika ada yang tidak valid, form menampilkan pesan error di bawah field dan fungsi mengembalikan false — sehingga proses upload tidak dilanjutkan.

static Future<Map<String, int>> getAdminStats() async {
  // Future.wait() menjalankan semua query BERSAMAAN (paralel)
  // Jika masing-masing butuh 200ms, total hanya ~200ms (bukan 800ms)
  final results = await Future.wait([
    _db.collection('users').count().get(),
    _db.collection('products')
       .where('isActive', isEqualTo: true)
       .count().get(),
    _db.collection('orders').count().get(),
    _db.collection('donations').count().get(),

  // results adalah List — urutan sama dengan urutan Future di atas
  return {
    'users':     results[0].count ?? 0,
    'products':  results[1].count ?? 0,
    'orders':    results[2].count ?? 0,
    'donations': results[3].count ?? 0,
  };
}

// Status flow: pending → processing → shipped → delivered
static Future<void> updateOrderStatus(
    String orderId, String status) async {

  // Update field status di dokumen pesanan di Firestore
  await _db
      .collection('orders')
      .doc(orderId)
      .update({
        'status': status,
        // serverTimestamp() = waktu server Firebase, bukan waktu device
        'updatedAt': FieldValue.serverTimestamp(),
      });

  // Kirim email notifikasi ke pembeli saat status menjadi 'shipped'
  if (status == 'shipped') {
    _notifyBuyerShipped(orderId); // non-blocking, tidak di-await
  }
}

        'city': _cityController.text.trim(),
        'phone': _phoneController.text.trim(),
        'bio': _bioController.text.trim(),
        'avatar': avatarUrl ?? '',
      },
    );

    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('Profil berhasil diperbarui!')),
      );
    }
  } finally {
    if (mounted) setState(() => _isLoading = false);
  }
}

Pertanyaan yang Mungkin Ditanya

Q: Bagaimana keamanan panel admin? Apa user biasa bisa mengakses halaman /admin?
AdminScreen mengecek UserModel.isAdmin di initState(). Jika user bukan admin, langsung redirect ke home menggunakan Navigator.pushReplacementNamed(context, '/home'). Di HomeScreen, tombol ikon admin hanya ditampilkan jika _isAdmin == true. Role admin hanya bisa diset lewat Firestore dan tidak bisa diubah oleh user sendiri dari app.
Q: Apa keuntungan Future.wait() dibanding await berurutan?
Dengan await berurutan, 4 query masing-masing 200ms akan membutuhkan total 800ms karena dijalankan satu per satu. Dengan Future.wait([...]), semua query berjalan bersamaan (paralel) sehingga total hanya sekitar 200ms. Ini penting untuk dashboard statistik agar tidak membuat pengguna menunggu lama.
Q: Apa itu FieldValue.serverTimestamp() dan kenapa lebih baik dari DateTime.now()?
FieldValue.serverTimestamp() menggunakan waktu dari server Firebase, bukan dari perangkat user. Ini lebih akurat karena waktu perangkat user bisa berbeda (salah setting, timezone berbeda). Untuk data seperti waktu pesanan dibuat atau diupdate, waktu server jauh lebih dapat diandalkan.
Q: Bagaimana admin bisa mengubah konten banner homepage tanpa update app?
Admin mengisi form di tab "Site Settings" di AdminScreen. Saat disimpan, data ditulis ke Firestore di app_config/site_settings. HomeScreen membaca dokumen yang sama setiap kali dibuka menggunakan FutureBuilder. Karena data dibaca langsung dari Firestore, perubahan yang dibuat admin langsung terlihat di app semua pengguna tanpa perlu merilis update.
